## Подтверждено в Chromium

Воспроизводимый сценарий: `scripts/check_three_viewer_browser.py` (Playwright
1.62.0, Chromium 1234; нужны системные библиотеки и шрифты Chromium).
Тест выполняет поставляемый компонент с настоящими iframe, BroadcastChannel,
кнопками, клавиатурой и перетаскиванием. Инспекция состояния добавляется только
в HTTP-ответ теста, не в поставляемый JS.

- Три куста, два устья в редактируемом кусте: перемещение P2 не меняет устья
  P1/P3 и целевые точки скважин в клиентском состоянии.
- Текущий маркер, исходный контур, ортогональные составляющие смещения,
  одна плашка дельт, Undo/Redo/Reset/Cancel, переход между объектами.
- Apply отправляет только изменённый куст. После ответа новая позиция становится
  исходной, история очищается, новая операция Undo возвращает к новой исходной
  позиции. Количество массивов истории не растёт при обновлениях сцены.
- Режим поворота и выбор объекта восстанавливаются после обновления данных.
- Cancel очищает также Redo геометрически неизменённых объектов: отменённая
  сессия не оставляет скрытых правок для следующей сессии.
- Пока операция не подтверждена, редактирование мышью/клавиатурой,
  история, Cancel и выход заблокированы, в том числе после тайм-аута.
  Выбор объекта для осмотра разрешён; повтор отправляет ту же операцию.

Ответ сервера в этих тестах моделируется через настоящий `streamlit:render`.
Это доказывает поведение компонента, но **не атомарность Python-применения,
корректность пересчёта, кеша или полную интеграцию Streamlit**.

## Исправленный воспроизведённый P0: поздний ответ стирал новый черновик

До исправления воспроизведено с управляемыми браузерными часами:

1. Изменить `well-b / t3`, нажать «Сохранить изменения».
2. Не доставлять ответ; перевести часы на 13 секунд вперёд.
3. После сообщения «Нет подтверждения — повторить» переместить t3 ещё раз.
4. Доставить результат первого сохранения.

Наблюдение (X, Y, Z):

| Состояние | Координаты |
| --- | --- |
| Отправленное | 603.713906763541, 530.7152330911474, 900 |
| Более новый черновик | 605.67023172119, 520.9084602957738, 900 |
| После позднего ответа | 603.713906763541, 530.7152330911474, 900 |

Причина старого поведения: тайм-аут снимал блокировку; `applyViewerPayload` при поступлении
данных безусловно пересоздаёт исходное и текущее состояние. Ответ не связан
явным подтверждением с отправленной редакцией. Наличие `nonce` только в
событии и дедупликация последнего события на Python-стороне этого не решают.

Реализовано и проверено после исправления:

- ACK содержит nonce и статус applied/noop/error. Передаётся отдельным аргументом
  компонента, не инвалидирует сериализацию геометрии и доставляется при том же
  digest. ACK хранится раздельно для каждого 3D-представления.
- Тайм-аут оставляет отправленную геометрию заблокированной. Повтор меняет только
  delivery_attempt (чтобы Streamlit получил новое событие), но не nonce/координаты.
- Python хранит квитанции обработанных операций; старая повторная доставка
  после более новой операции не применяет старые координаты заново.
- Runtime игнорирует не относящиеся к операции обновления во время ожидания,
  а также обновления полной сцены поверх нового несохранённого черновика.
  Обёртка при этом не заменяет канал связи и не перезагружает iframe.
- Ошибка отправки до первой доставки и явный error ACK сохраняют черновик,
  восстанавливают доступ к истории/отмене. Ошибка ACK не изображается как успех.
- Браузерная матрица повторно PASS: ожидание 13 с, запрет новой правки,
  точный повтор, поздний успех, новый черновик + дублирующий старый ответ,
  error/noop с неизменным digest, отказ транспорта. Проверяются координаты,
  идентичность сцены, история и состояние кнопок, а не только наличие текста.

## Атомарность совместного Apply

Цели и куст теперь подготавливаются в отдельном словаре состояния. Редакторы
создают новые записи/настройки; тяжёлые неизменённые траектории и кеши не копируются.
В Session State записываются только заменённые/добавленные/удалённые ключи после
успешной подготовки обеих частей. Ошибка записи откатывает уже записанные ключи.

Добавлены тесты:

- ошибка планирования куста после подготовки его новых координат и новой цели:
  все исходные ключи сохраняют прежние значения и объектную идентичность;
- ошибка записи Session State после части записей: состояние восстановлено;
- успешная правка: нет изменения входных записей, сохранены ссылки на чужую
  скважину и anti-collision-кеш;
- неверный индекс/неизвестная скважина/NaN/неверное окно ЗБС отклоняются целиком,
  а не подтверждаются как якобы успешный no-op;
- no-op получает ACK через один fragment rerun, не меняя instance_token;
- повторные события двух разных представлений не вызывают цикл rerun.

Эти проверки не заменяют полную сквозную проверку расчёта, CRS/пилотов и кеша.
